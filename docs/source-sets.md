# Наборы источников VPN

## Что означает «Набор источников»

Номера **1**, **2** и **3** — это три именованных списка URL для загрузки VPN-конфигураций. Это не версии каталога и не уровни качества. Номер выбирает, какой список ссылок использовать при следующем запуске проверки.

Наборы нужны для VPN-режима. Встроенный каталог содержит подписки и публичные списки конфигураций вроде VLESS, VMess и Trojan. В режиме **HTTP / SOCKS** эти наборы не используются: для него нужно добавить подходящую подписку или вставить HTTP/HTTPS/SOCKS-прокси вручную.

## Откуда берутся списки

Исходные списки поставки находятся в [`bin/sources.json`](../bin/sources.json). Файл представляет собой JSON-объект с ключами `"1"`, `"2"` и `"3"`; значение каждого ключа — массив URL. Одна ссылка обычно ведёт на список или подписку, которую приложение загружает во время проверки.

Текущее число ссылок во встроенных списках поставки:

| Набор | URL во встроенном каталоге | Примеры адресов из списка |
| --- | ---: | --- |
| 1 | 71 | `sub.amiralter.com/config`, `itsyebekhe.github.io/PSG`, `f0rc3run.github.io/F0rc3Run-panel` |
| 2 | 87 | `NiREvil/vless`, `nscl5/5`, `HakurouKen/free-node`, `Mosifree/-FREE2CONFIG` на GitHub |
| 3 | 12 | `HakurouKen/free-node`, `ALIILAPRO/v2rayNG-Config`, `0xRadikal/Free-v2ray-Configs`, `Au1rxx/free-vpn-subscriptions` на GitHub |

Это количество настроенных URL, а не количество прокси и не число работающих источников. Доступность внешних адресов меняется: отдельная ссылка может временно не отвечать, вернуть пустой список или данные неподдерживаемого формата.

## Почему количество в приложении может отличаться

При первом запуске GUI копирует встроенные списки в пользовательский файл `catalog-sources.json` в папке данных ProxySift. Этот файл — рабочая копия каталога:

- при добавлении или удалении ссылки изменяется выбранный набор в пользовательской копии;
- если для набора уже есть сохранённый список, он **заменяет** встроенный список этого набора, а не дополняет его;
- поэтому количество в подписи переключателя «Встроенный каталог» показывает URL из текущего сохранённого набора и может отличаться от количества в таблице выше;
- при обновлении приложения локальная копия сохраняется. Новые встроенные ссылки сами по себе не перезаписывают уже сохранённый набор; для целевых исправлений предусмотрены миграции известных адресов.

Например, надпись «85 источников» для набора 2 означает, что в активной локальной копии набора 2 сейчас 85 URL. В поставляемом `bin/sources.json` для него задано 87 URL.

## Как приложение использует выбранный набор

1. На экране «Проверка» в режиме **VPN** выберите набор 1, 2 или 3.
2. Переключатель «Встроенный каталог» включает или исключает URL выбранного набора из запуска.
3. Добавленные URL подписок подключаются дополнительно. Вставленные вручную ссылки на отдельные узлы также добавляются к выбранному входу.
4. При запуске приложение загружает выбранные URL, объединяет их с дополнительными входами и убирает точные дубликаты ссылок перед обработкой.
5. Из полученных данных извлекаются узлы, после чего выполняются разбор, дедупликация и этапы проверки VPN-пайплайна.

Если проверка сообщает, что нет источников, сначала проверьте режим и переключатель каталога. В HTTP / SOCKS встроенные VPN-наборы намеренно недоступны. В VPN-режиме при выключенном каталоге нужно добавить подписку или узлы вручную.

## CLI

CLI использует тот же формат `sources.json` и те же наборы:

```sh
proxy-rs --set 1
proxy-rs --set 2
proxy-rs --set 3
proxy-rs --set all
```

По умолчанию CLI выбирает `--set 3`. Для другого каталога можно указать `--sources <путь-к-json>`. Дополнительные URL задаются через `-u/--url`, а файл `-f/--file` может содержать URL подписок и готовые ссылки на узлы. GUI при запуске формирует собственный `run-sources.json` из активной локальной копии и передаёт CLI выбранный набор.

## Обновление поставляемых источников

Чтобы изменить исходные списки для новых установок или профилей без сохранённой копии, редактируйте соответствующий массив в `bin/sources.json`. GUI и CLI используют этот файл как источник встроенных значений.

Для уже существующих установок учитывайте `catalog-sources.json`: пользовательские наборы имеют приоритет над встроенными. Чтобы автоматически заменить конкретную устаревшую ссылку, добавьте адресную миграцию в `migrate_known_catalog_urls` в `src/app.rs`. Обновление встроенного JSON само по себе не должно стирать пользовательские правки.
